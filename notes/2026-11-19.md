Two schema-only PRs for tournaments: a public, throttled read of any published tournament (the first step of the embed widget) and the tables for divisions and multi-day events. Both migrations are on live and both deploys are out.

## Shipped

**Features**

- Anyone with a tournament's id can now read it through `get_public_tournament(id)`: teams, rosters (names only), pools, and matches with set scores once the schedule is published or play has started. Drafts return nothing; contact details, payment handles, chat and join requests are never included. Tournament tables stay closed to guests. Nothing in the app calls it yet; the embed page, framing headers and Share → Embed sheet come next (#330)

  ```mermaid
  sequenceDiagram
    participant C as Caller (guest / embed)
    participant API as PostgREST
    participant F as get_public_tournament (definer)
    participant PG as Postgres
    C->>API: POST rpc/get_public_tournament {p_id}
    API->>F: call (x-forwarded-for in request.headers)
    F->>PG: check_rate_limit('pubt:<md5 ip>:<id>', 120, 60s)
    alt over limit
      F-->>C: PT429 → HTTP 429
    end
    F->>PG: read tournament_public_snapshots
    alt copy under 15 s old
      F-->>C: saved payload + built_at
    else stale or missing
      F->>PG: advisory lock per tournament (others get the old copy)
      F->>PG: build_public_tournament(id) (non-draft only)
      F->>PG: upsert snapshot (or delete if draft/unknown)
      F-->>C: fresh payload + built_at
    end
  ```

  **Model changes**

  | Object | Change | Notes |
  | --- | --- | --- |
  | `tournament_public_snapshots` | added | Saved JSON per tournament; RLS on, no policies, no client grants |
  | `build_public_tournament(uuid) → jsonb` | added | SECURITY DEFINER; builds the public payload; not executable by clients |
  | `get_public_tournament(uuid) → jsonb` | added | SECURITY DEFINER, anon + authenticated; 15 s saved copy, 120 calls/min per address and tournament |

**Under the hood**

- Schema for Texas-AO-style tournaments: divisions (one bracket per range of finishes, counted per pool or by overall rank after pool play), tournament days, pool-play settings, and a fifth standings tiebreaker, `sets_won`. Expand only; existing tournaments behave as before and nothing in the app writes these yet (#299)

  **Model changes**

  | Object | Change | Notes |
  | --- | --- | --- |
  | `tournament_divisions` | added | Name, order, `from_place..to_place`, `fill_by` (pool_place / overall_rank), bracket type, 3rd-place match. Creator manages; club members read once published; guests nothing |
  | `tournament_days` | added | A multi-day tournament's days and stage (all / pool / bracket). Same access as divisions |
  | `tournament_matches.division_id` | added | Nullable, set null if the division is deleted |
  | `tournaments.pool_matches_per_team`, `warmup_minutes`, `house_rule` | added | Null = full round robin; warm-up default 0; one-line rule (≤280 chars, not enforced) |
  | `tournament_rules.pool_sets_played` | added | Fixed sets in pool play (2 = a 1–1 split is a tie); null = same as bracket |
  | `tournament_rules_tiebreakers_check` | changed | Now allows `sets_won` and up to five tiebreakers |
