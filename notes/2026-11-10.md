## Shipped

**Under the hood**

- Usage metrics, part 1 of 3: each app open is a session (new one after 30 minutes away or when the account changes), a heartbeat every minute while the app is visible, and `session_start` / `screen_view` events that record screen types like `/event/[id]`, never ids. A per-minute "online now" sample and a nightly daily peak/average feed the admin Metrics screens coming in part 2. None of it is readable by clients. No opt-out; the Privacy Policy now explains usage data, that only admins see it, and the 180-day / daily-totals retention (#232)

  No screenshots: the comparison ran on all 10 screens (mobile and desktop) and none changed visibly.

  | Object | Change | Notes |
  |---|---|---|
  | `app_sessions` | added | One row per app open: user (from `auth.uid()`) or device id, platform, app version, current screen type, started / last seen. RLS on, no policies: no client reads or writes; only `app_heartbeat()` writes. Cascades on account deletion; pruned after 180 days |
  | `app_online_samples` | added | People online (seen in last 90 s) each minute, signed-in count and by platform. No client access; kept 30 days |
  | `app_online_daily` | added | Each America/Chicago day's peak, when, and average. No client access; kept forever |
  | `app_events.session_id`, `app_events.app_version` | added | Nullable columns; clients may insert them like the other event columns |
  | `app_heartbeat(session, anon, platform, version, screen)` | added | SECURITY DEFINER, anon + authenticated. Ignores bad input; only the device that opened a session can update it, never moves it to another user, at most one heartbeat per 30 s |
  | `sample_app_online()` | added | SECURITY DEFINER, no client EXECUTE |
  | `rollup_app_online(days)` | added | SECURITY DEFINER, no client EXECUTE; recomputes the last 7 days so a missed night catches up |
  | cron `sample-app-online` | added | Every minute |
  | cron `prune-app-online` | added | 09:23 UTC: roll up days, prune samples > 30 days and sessions > 180 days |

  ```mermaid
  sequenceDiagram
    participant App
    participant PG as Postgres app_heartbeat()
    participant Cron as pg_cron
    App->>App: launch / back after 30 min / account change → new session id
    App->>PG: insert app_events (session_start, screen_view + session_id, app_version)
    loop every minute while visible
      App->>PG: rpc app_heartbeat(session, device, platform, version, screen)
      PG->>PG: upsert app_sessions (user from auth.uid(), same device only, ≥30 s apart)
    end
    Cron->>PG: sample-app-online (every minute)
    PG->>PG: count sessions seen in last 90 s → app_online_samples
    Cron->>PG: prune-app-online (09:23 UTC)
    PG->>PG: rollup_app_online() → app_online_daily, then prune old samples and sessions
  ```
